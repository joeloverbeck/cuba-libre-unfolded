# Domain docs

Use a single-context layout: `GLOSSARY.md` at the repository root and numbered ADRs in `docs/adr/`.

Before domain exploration, read the glossary and ADRs relevant to the work. If they do not exist, proceed silently; create them only when actual terminology or decisions are resolved through authorized domain-modeling work.

Use glossary terms consistently in issues, proposals, code, and tests. If a concept is missing, reconsider an invented synonym or identify the gap for later domain modeling.

Surface conflicts with an existing ADR explicitly. Glossary entries and ADRs remain subject to the constitution and foundations; unresolved implementation details do not become accepted product policy by being documented.
